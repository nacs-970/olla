<objective>
Build the Phase 1 Walking Skeleton: a from-scratch installable `olla` CLI that runs a reason-act-observe loop — `olla "task" --model <name>` calls `ollama.chat()`, parses `<tool>/<args>/<final>` tags from the response (tolerant of markdown fences, prose, and unclosed tags), executes shell commands via `shlex.split()` + `subprocess.run(shell=False)`, prints visible step progress, truncates large outputs before they re-enter the model's context, and prints the final answer.

This is intentionally ONE plan covering the full vertical slice (CLI -> loop -> ollama.chat -> parser -> shell tool -> printed final answer) per the Walking Skeleton MVP pattern — every module is small (parser ~20 lines, shell tool ~15 lines, loop ~30-40 lines, prompts ~20 lines), so 6 small per-module tasks plus one packaging checkpoint stay well within a single plan's context budget despite exceeding the generic 2-3 task guideline.

Purpose: Prove the entire stack end-to-end with one real (non-mocked) integration path before any safety gating (Phase 2), file tools (Phase 3), or memory (Phase 4) is added on top. This plan covers success criteria 1-5 of Phase 1's 6; criterion 6 (`--smoke-test`) is Plan 2, built on these same modules.

Output: A pip-installable `olla` package (`src/olla/` + `pyproject.toml`) with passing unit tests for the parser, shell tool, and loop, plus a manually-verified end-to-end run against a real local Ollama model. Also produces `01-SKELETON.md` recording the architectural decisions this slice establishes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model output -> parser | The local Ollama model's text response is untrusted-ish input: it can contain anything, including attempted shell metacharacters, malformed tags, or adversarial-looking strings. |
| Parser -> shell tool | `parsed["args_raw"]` (a string chosen by the model) flows into `run_shell()` and becomes an argv via `shlex.split()`. |
| Shell tool -> OS process | `subprocess.run(argv, ...)` executes a real process on the user's machine with the user's privileges. |
| pip install -> developer machine | `pyproject.toml` declares 6 third-party packages installed via `pip install -e ".[dev]"`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering / Elevation of Privilege | `src/olla/tools/shell.py:run_shell` | mitigate | `shlex.split(args_raw)` + `subprocess.run(argv, shell=False, ...)` (Task 4). Shell metacharacters (`;`, `|`, `&`, `$()`, backticks) become literal argv tokens passed to `execve`, not shell control operators — no shell is invoked to interpret them.
