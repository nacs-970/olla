<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output -> dry-run preview | The single model response in `--dry-run` mode is untrusted; the preview must reflect the REAL gate decision (via `check()`), never a placeholder, so the user's preview-based trust decision is accurate (Pitfall 8). |
| model loop -> repetition counter | A stuck or adversarial model emitting the same shell call repeatedly is a resource-exhaustion vector; the counter must trigger before the 3rd execution, not after. |
| repetition message vs. max-steps message | Two independent abort paths must remain textually and behaviorally distinct so the user's remediation (kill a stuck model vs. let it keep working / increase --max-steps) is correctly informed — this is the SAFE-03 regression's purpose. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Information Disclosure | loop.py dry-run branch | accept | `--dry-run` reveals BLOCK reasons and CONFIRM/ALLOW classification for the model's proposed command before execution. This is the intended UX (D-09/D-10) — a local single-user CLI previewing its own next action is not a disclosure boundary; accepted with no mitigation needed. |
| T-02-06 | Tampering (dry-run executes something) | loop.py dry-run branch | mitigate | Dry-run branch is structurally separate from the main loop — `return`s before reaching `run_shell`/`Confirm.ask` on every dispatch path (Task 1); verified by tests asserting `run_shell.call_count == 0` and `Confirm.ask.call_count == 0` across all 6 dry-run scenarios |
| T-02-07 | Denial of Service (runaway repeated shell calls) | loop.py repetition counter | mitigate | `(tool, tuple(argv))` signature tracked across iterations (D-08); 3rd consecutive identical signature aborts with a distinct diagnostic before the 3rd `run_shell` call (D-06/D-07), verified by `run_shell.call_count == 2` on the 3x-repeat test |
| T-02-08 | Repudiation (abort path ambiguity) | loop.py repetition message vs. max-steps message | mitigate | The two abort messages use disjoint wording (`"olla stopped: same shell call repeated 3x..."` vs. `"Reached max steps (N) without a <final> answer."`); SAFE-03 regression test asserts both that the max-steps message fires for varied calls AND that the repetition message does not appear in that run, preventing either message from silently shadowing the other |

All blocklist/confirm-gate threats (T-02-01 through T-02-04) are owned by 02-01's threat model; T-02-SC (rich dependency) is also owned by 02-01 (already a declared dependency by the time this plan runs).
</threat_model>
