# Phase 02.1 Plan 01 Summary: Foundational Provider Layer

## Overview
Built the foundational provider layer in `src/olla/providers/` enabling `olla` to interact with remote OpenAI-compatible APIs (specifically OpenRouter and OpenAI) alongside local Ollama instances.

## Key Changes
- **Dependency:** Added `httpx>=0.27.0` to `pyproject.toml`.
- **Protocol:** Defined `Provider` protocol, `StreamChunk` dataclass, and `ProviderError` in `src/olla/providers/base.py`.
- **Ollama Provider:** Wrapped `ollama.chat()` and streaming in `OllamaProvider` (`src/olla/providers/ollama.py`).
- **OpenAI-Compatible Provider:** Implemented `OpenAICompatProvider` (`src/olla/providers/openai_compat.py`) with:
  - Synchronous HTTP streaming via `httpx.Client.stream`.
  - SSE line parsing with reasoning/thought token extraction.
  - Client-side sliding window buffer (`stream_with_stop_buffer`) ensuring `</args>` never leaks into output.
  - Automatic retries with exponential backoff (`1s`, `2s`, `4s`) for HTTP 429 and 5xx responses.
  - Dynamic context length resolution from `/models`.
- **Factory & Routing:** Implemented `get_provider()` in `src/olla/providers/__init__.py` routing by model prefix (`openrouter/`, `openai/`, `ollama/`, or unprefixed default).
- **Unit Tests:** Created comprehensive test suite in `tests/test_providers.py` covering routing, missing API keys, stop buffering, reasoning extraction, retry backoff, and dynamic context lengths.
