## Phase Goal

**As a** user running olla, **I want to** trust olla with shell execution because every dangerous action is gated by a confirm prompt and blocklisted patterns are caught before they run, **so that** I can run agentic shell tasks without fear of olla executing a destructive command.

<objective>
Deliver the first end-to-end safety slice: a pure `src/olla/safety.py` decision module (ALLOWLIST + blocklist rule table + `check(argv, yes) -> Decision`), wired into `run_loop`'s shell-tool dispatch as a real confirm-gate (BLOCK never executes, CONFIRM shows a `rich.prompt.Confirm.ask` prompt with EOFError treated as decline, ALLOW runs immediately), with `--yes` threaded from `cli.py` through to `run_loop` and `rich>=13` added as a dependency.

Purpose: This is the first user-observable change in Phase 2 — before this plan, shell commands always ran unconditionally; after it, a user running `olla "task"` sees olla actually refuse blocklisted commands and prompt before anything else. `safety.py` is also the single source of truth that 02-02's `--dry-run` preview will call, so dry-run output can never lie about what a real run would do (Pitfall 8).

Output: `src/olla/safety.py` (new), `tests/test_safety.py` (new), `src/olla/loop.py` (modified — gate dispatch + signature), `src/olla/cli.py` (modified — `--yes` wiring, notice removed), `tests/test_loop.py` (modified — new gate tests), `tests/test_cli.py` (modified — `--yes` rewrite + signature assertions), `pyproject.toml` (modified — add `rich>=13`).
</objective>
