Close the SOLE blocking gap (CR-01) from `02-VERIFICATION.md` round 5: `src/olla/safety.py` line 7 imports `typing.NotRequired`, a PEP 655 symbol added in Python 3.11. `pyproject.toml` declares `requires-python = ">=3.10"` with no `typing_extensions` fallback, so on a genuine Python 3.10 interpreter `import olla.safety` raises `ImportError` at module load — this propagates through `loop.py` and `cli.py`, so the entire `olla` CLI fails to start on the project's own declared minimum platform.

All five behavioral truths (SAFE-01..04, LOOP-04) are already verified on Python >=3.11 and require NO re-implementation — only the import needs fixing so they are *reachable* on 3.10.

Fix (Option 3, per 02-VERIFICATION.md's three options and the project's minimal-dependency constraint — `ollama`, `rich`, `click` only, no `typing_extensions`): drop `NotRequired` entirely. Change `from typing import Literal, NotRequired, TypedDict` to `from typing import Literal, TypedDict`, and change `class Decision(TypedDict):` to `class Decision(TypedDict, total=False):`. `TypedDict(total=False)` makes ALL keys optional at the type-checker level (slightly weaker than `NotRequired` marking only `reason` optional) — this is a type-checker-only concern; the project ships no type checker (dev deps: pytest, pytest-mock, ruff — no mypy), and `TypedDict` itself performs NO runtime enforcement, so this introduces zero runtime behavior change. `check()` always sets `kind` on every return path (4/4 branches), so the type-checker weakening is purely theoretical.

Verified safe via call-site analysis: `decision["reason"]` is read in `loop.py` only at lines 65 and 111, both inside `kind == "BLOCK"`-gated branches, and `check()`'s two BLOCK-returning branches (lines 255, 259) both set `"reason"` unconditionally. No `.get()` calls needed, no `KeyError` possible.

Regression safeguard: `ruff check --target-version py310` was tested against the CURRENT (broken) safety.py and does NOT flag the `NotRequired` import — ruff's `target-version` governs which fixes/rewrites it suggests, not forward-incompatible-symbol detection. It is therefore NOT a viable automated safeguard for this class of bug. The safeguard instead consists of (a) a new static pytest test that greps `safety.py`'s own source for `NotRequired`/`Required` and fails if either is present (portable across all Python versions, including this dev machine's 3.14 — it catches the *symbol*, not the import-time failure, which cannot be exercised on 3.14), and (b) a short documented note (in `tests/test_safety.py`, as a comment near the new test) describing how a developer/CI with access to a 3.10 or 3.11 interpreter should run `python3.10 -c "import olla.safety"` to confirm the actual import-time fix.
