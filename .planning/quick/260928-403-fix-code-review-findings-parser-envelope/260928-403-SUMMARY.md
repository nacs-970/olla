# Phase quick-260928-403 Plan 01: Fix code-review findings (parser envelope, loop, benchmark) Summary

The parser keeps a payload `<final>` opaque even when a fence line or `File:` sits between the tool envelope and `<args>`. The loop accepts tag-free prose as final only after a tool step and never for tag-like, fenced, or JSON replies. The loop never executes a tool call that appears only in reasoning. Empty replies add no history. The benchmark headline uses paired complete-set means, and the results file is written atomically.

## What changed

- **Fix 1 (parser):** In `TOOL_ENVELOPE_ARGS_RE`, the trailing `\s*` before `<args>` is now `[^<]*`. No other parser logic changed. Both reproduced inputs now parse as tool calls. The existing prose-args regressions from 260924-mml still pass.
- **Fixes 2 and 4 (prose-as-final):** `_prepare_action(content, *, allow_prose_final=False)` adds `_TAG_LIKE_RE` and `_CODE_FENCE_RE`. `run_loop` keeps a local `tool_step_done`. It is set after the repetition-stop check when `action.kind != "none"`, and it is passed as `allow_prose_final=tool_step_done`. Dry-run passes `allow_prose_final=False` explicitly.
- **Fix 3 (reasoning fallback):** The `_stream_model_turn` fallback condition changed from `!= "none"` to `== "final"`.
- **Fix 5 (empty reply):** The nudge branch became `elif content.strip():`, so an empty reply appends nothing. The assistant-append skip and `_track_repetition` placement are unchanged, so 3 identical empty replies still stop the run. The nudge text is unchanged.
- **Fix 6 (paired headline):** New pure helper `paired_means(records, metric)`. `summarize` adds `paired_mean_prompt_tokens` and `paired_mean_completion_tokens` for each arm, plus `paired_sets` and `dropped_sets`. The signed % uses the paired means. `print_report` prints the paired means and a `paired over N complete (task, repeat) sets; M dropped (some arm had no value)` line for prompt and for completion. The WARNING tail was reworded as the plan asked.
- **Fix 7 (atomic write):** `_write_json` serializes first. It writes a `NamedTemporaryFile` in `path.parent`, then flushes, fsyncs, and closes it, then calls `os.replace`. On any exception it unlinks the temp file and re-raises.

## Fix-3 / fix-5 reconciliation

The fix-3 spec says that after the fallback change "the action is none and the nudge is sent". After fix 3, a reply whose content is empty and whose reasoning holds only a tool call returns the empty content. That content goes through the fix-5 empty-reply path, which records no assistant turn and sends no nudge. The next step is a plain retry. **Fix 5 wins.** `test_run_loop_tool_in_reasoning_with_empty_content_never_executes` asserts four things: `run_shell` is not called, no nudge is sent, no blank assistant message is added, and no two user messages are adjacent. The fix-4 case differs because its content is non-empty (`Sure.` with a tool call only in reasoning). That case still gets exactly one nudge and no execution (`test_run_loop_step_one_prose_with_tool_only_in_reasoning_is_nudged`).

## Fix-7 test approach

No original review text is in the repo, so this section describes only what the test does. The test does not simulate a crash partway through the write, and it does not try to reproduce a truncated file. `test_write_json_is_atomic` injects the failure at the commit point:
1. It writes an initial payload.
2. It monkeypatches `bench.os.replace` to raise `OSError`.
3. It calls `_write_json` with a new payload and expects the error.
4. It asserts that the target still holds exactly the old JSON and that `tmp_path` holds no leftover temp file.

Against the old code the RED result was `Failed: DID NOT RAISE`. The old code wrote in place and never called `os.replace`, so the new payload overwrote the file. The test therefore proves the atomic mechanism: temp file, then replace, then cleanup on failure. It does not reproduce a real truncation.

The code was not changed for this.

   2. A mocked read_file call runs.
   3. Prose ends the run on the third call.
   It asserts 3 model calls, no nudge, and the last assistant message `<final><prose></final>`.
